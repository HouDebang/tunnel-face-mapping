## 数据来源与边界

- 掌子面照片：`examples/real_face_RK4_970.jpg`（4096×3072）。
- 素描图、候选分区、候选结构面迹线、统计值：`outputs/real_RK4_970/`。
- 成果表中的 3,035 条候选迹线、98,883 px 总长、0.00786 px⁻¹ P21 均来自该次运行的 `results.json`。
- 岩性类别在本次运行中仍为 `unknown`，画面中使用“候选区域 / 待复核”表述，不把视觉分区冒充实测岩性。
- 结构面迹线为算法候选，不是人工确认的结构面条数；未进行尺度标定，因此不显示米制比例尺。
- **机器人和隧道是程序化概念示意**，不是实拍，也不是 AI 生成的实景视频。这样做的目的是让产品逻辑、路线、窗口和成果对应关系完全可控，并避免虚构设备结构。
- 画面没有虚构品牌、随机中文、乱码或水印；最终字幕中保留了“概念演示”和数据边界说明。

## 重新生成

```powershell
# 1) 从真实成果生成动画资产与几何数据
.\.venv\Scripts\python.exe animation\prepare_assets.py

# 2) 生成中文旁白和 60 秒音轨（需要网络访问 Edge TTS）
.\.venv\Scripts\python.exe animation\make_audio.py

# 3) 逐帧渲染并编码
.\.venv\Scripts\python.exe animation\render_video.py --out tunnel_geo_sketch_60s.mp4
```

只渲染指定片段：

```powershell
.\.venv\Scripts\python.exe animation\render_video.py --start 27 --end 40 --out photogrammetry_27_40.mp4
```

## 画面控制点

- 所有时间点通过 `window.seek(t)` 定位，浏览器逐帧截图，因此同一 `t` 的输出可复现。
- 机器人在全片使用同一个 SVG 资产；只改变位置、比例、轻微姿态和灯光状态，不改变履带、相机数量或安装关系。
- 建图窗口与摄影测量窗口是两种不同的成果：前者是隧道空间点云/路径/机器人定位，后者是掌子面正射影像/纹理网格。
- 目标点在路径规划时出现，行进时持续存在，到达后与机器人位置重合，再显示“测量位置已到达”。
- 自动素描按“原始影像 → 候选分区 → 候选迹线 → 综合素描 → 成果表”的顺序逐层出现，不是突然跳出一张成图。
- 旁白与字幕的时间轴在 `make_audio.py` / `app.js` 中分别维护；修改字幕时请同步两处。

## 技术参数

- 画幅：1920×1080，16:9。
- 帧率：30 fps；总帧数 1,800。
- 视频：H.264 High，CRF 18，yuv420p，BT.709。
- 音频：AAC-LC，48 kHz，立体声，192 kbps。
- 旁白：Microsoft Edge Neural Voice `zh-CN-YunyangNeural`，rate -4%，pitch -2Hz。
- 字幕：简体中文，烧录在画面内，同时提供 SRT。

## 可替换项

如果后续拿到真实机器人产品参考图、真实平台界面截图或带尺度标定的成果，可以优先替换：

1. `index.html` 中的 `#robotArt` SVG 资产（保持履带、相机数量和支架关系一致）。
2. `assets/face.jpg`、`assets/sketch.jpg` 和 `data/geometry.js`（重新运行 `prepare_assets.py`）。
3. 成果表字段与数值（`index.html` 的 `.result-table` 和 `app.js` 中对应文本）。
4. 旁白文本（`make_audio.py` 的 `LINES`）与字幕（`make_audio.py` 的 `subs`、`app.js` 的 `SUBS`）。
